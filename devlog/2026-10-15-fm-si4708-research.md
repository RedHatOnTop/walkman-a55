# FM radio (Si4708) — interface and audio path research

2026-10-15. Worker C of the connectivity brief (`docs/mt6620-connectivity-hal-brief.md`). Research
only, device-free. First draft by DeepSeek from context Claude extracted (module symbols/strings,
Sony's `fm_tuner` strings, the board file, CXD3778GF codec source); Claude checked the board wiring
against the source and corrected the test steps. Tags: **VERIFIED** = visible in a file or binary
named here; **INFERRED** = reasoning, needs the device.

## 1. Driver interface

- `work/device/system/lib/modules/radio-si4708icx.ko`: Sony I2C driver, `alias i2c:Si4708icx`,
  `parm deemphasis:int`, vermagic `3.10.26 SMP preempt mod_unload ARMv7`. **VERIFIED** (modinfo)
- It imports `__video_register_device`, `video_ioctl2`, `video_device_alloc`, `video_devdata`,
  `v4l2_ctrl_query_fill`, so it is a **V4L2 radio device**, not ALSA or input. **VERIFIED** (nm -u)
- Its source is not in Sony's GPL tarball: Kconfig names `radio-i2c-si4708icx`, but only upstream
  `drivers/media/radio/si470x/` and `include/linux/platform_data/icx_si4708.h` are there.
  **VERIFIED**
- Sony's `/system/xbin/fm_tuner` (interactive, prompt `fmtuner>`) opens `/dev/radio0` and uses only
  `VIDIOC_S/G_FREQUENCY`, `VIDIOC_G/S_TUNER`, `VIDIOC_S/G_CTRL`. Its commands are `XXX` (tune),
  `mute`, `unmute`, `autoscan`, `rssi XXX`, plus stereo/mono. **VERIFIED** (strings)
- Board wiring (`arch/arm/mach-mt8590/icx_radio_i2c_devs.c`): I2C bus 2, 7-bit address `0x10`,
  name `Si4708icx`, reset GPIO278, `i2c_timing = 400`. **VERIFIED**
- The driver has deemphasis (`bcr_set_deemphasis_mode`) and RDS register names (`RDSA`–`RDSC`).
  Frequency units, spacing and the deemphasis default are not derivable from the strings. **VERIFIED**
  that they are absent.

## 2. Audio path

- The CXD3778GF ALSA control `analog input device` is an enum: `off`, `tuner`, `mic`, `line`,
  `directmic` (`sound/soc/codecs/cxd3778gf/cxd3778gf.c`). **VERIFIED**
- `tuner` calls `switch_tuner(ON)` (`cxd3778gf_control.c`): AIN2 input → PGA2 (+3 dB) → ADC2 →
  CIC2 → **SDOUT2** (serial data out to the SoC). The line-in/analog-bypass register writes in that
  function are commented out. **VERIFIED** (source + its comments)
- So the tuner audio comes back to the SoC as a digital I2S stream. It is not an analog bypass to the
  headphone amp. **INFERRED**. The likely carrier is the `CXD3778GF_STD` link on `mt8590-i2s2`,
  but no capture PCM is proven, so whether Android needs a capture → playback loopback is open.
  **INFERRED**

## 3. Minimal operator test (Sony host side, outside the container)

Operator-run, root on the Sony host as in the audio test. Do it with the Sony stack stopped
(`hagodaemons.sh stop`), so Sony's path manager does not override the mixer.

```sh
grep radio_si4708icx /proc/modules || insmod /system/lib/modules/radio-si4708icx.ko
ls -l /dev/radio0 ; dmesg | grep -i si470 | tail
amixer -c0 cset name='analog input device' tuner
amixer -c0 cset numid=43 1      # Master Switch on      (proven in the audio test)
amixer -c0 cset numid=16 0      # analog playback mute off
amixer -c0 cset numid=13 10 ; amixer -c0 cset numid=10 45 ; amixer -c0 cset numid=42 55
/system/xbin/fm_tuner
```

At `fmtuner>`: the help line is `XXX : tune XX.XMHz`, so `900` probably tunes 90.0 MHz. That is
**INFERRED**; try `90.0` if it is rejected. Then `unmute`, `rssi 900`, `autoscan`.

What it settles: `/dev/radio0` exists, tuning works, and RSSI and stereo are reported. If you hear
the station, the codec routes ADC2 to the DAC internally and no loopback is needed. If RSSI is fine
but there is no sound, the stream reaches the SoC and someone must capture and replay it. An
NW-A55L (US) unit may have no tuner at all.

## 4. Android path

Android 5.1 has no standard FM HAL, and the CM image ships no FM app. **VERIFIED**

- **Recommended: a small app + JNI over V4L2.** Bind `/dev/radio0` into the container (or let the
  container's ueventd create it, as with `/dev/wmtWifi`). The JNI issues the same `VIDIOC_*` calls as
  `fm_tuner`. The audio route (`analog input device = tuner`) is set by our `audio.primary` HAL as an
  input-device parameter, or by the app. If section 3 shows a loopback is needed, the JNI captures
  through tinyalsa and plays to `hw:0,0`. **INFERRED**
- Alternative: adapt AOSP `packages/apps/FMRadio`, whose JNI targets MediaTek `/dev/fm` ioctls,
  through a V4L2 shim. **INFERRED, unchecked**: its JNI ioctl set has not been read.
- Wrapping Sony's `fm_tuner` from a root shell would tune but leaves the audio route and the UI
  unsolved.
